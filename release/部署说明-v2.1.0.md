> 站点数据（分组 / 站点 / 用户 / 设置）全部原地保留。
>
> **v2.0.0 的部署说明仍然有效**（`部署说明-v2.0.0.md`），里面那四个坑

> **本文件只讲 v2.1.0 新增的东西。**

## 0. 这次改了什么

| | 内容 |
| --- | --- |
| 新增 | 登录页「记住我」勾选框：勾 = 长期保持登录（关浏览器也不掉线）；不勾 = 关浏览器即失效 |

## 1. 🔴 新增一步：建会话目录（本次唯一的必做动作）

v2.1.0 把 PHP 的会话文件从 `/tmp` 改到**站点根之外的独立目录**：

```
/www/wwwroot/nav-data/sessions
```

**为什么必须这么做**：宝塔的 `session.save_path` 默认是 `/tmp`，而 `/tmp` 是整台
服务器上所有 PHP 程序共用的。会话垃圾回收（GC）是按「当前请求的
`session.gc_maxlifetime`」去扫**整个目录**的 —— 宝塔面板自己也是 PHP，它的
`gc_maxlifetime` 只有 1440 秒（24 分钟），它一触发回收，就会把我们的
`sess_nav_sid*` 一起删掉。表现就是：**明明勾了记住我，20 分钟没点就又掉线了。**

改成独立目录后，回收范围只限本站，和其他 PHP 程序彻底隔离。

```bash
# 1) 建目录并授权给 www（站点根属主是 root，www 自己建不了）
mkdir -p /www/wwwroot/nav-data/sessions
chown www:www /www/wwwroot/nav-data/sessions
chmod 700 /www/wwwroot/nav-data/sessions

# 2) 确认
ls -ld /www/wwwroot/nav-data/sessions
#   drwx------ 2 www www ... /www/wwwroot/nav-data/sessions
```

> ✅ 该目录在 `/www/wwwroot/nav-data/` 下面，而 `nav-data/` **本来就在
> `open_basedir` 白名单里** —— 所以**不需要改 `.user.ini`**。
>
> ✅ 它在站点根之外，HTTP 拿不到（会话文件里存的是 `user_id`，泄漏等于被人登录）。
>
> 如果这步没做：代码会**降级回 `/tmp`** 继续跑，不会报错，但「记住我」就会时不时失效。
> 属于「不报错的坑」，务必确认目录存在且属主是 `www`。

## 2. 覆盖文件

```bash
# 上传 release/nav-v2.1.0-deploy.zip 到服务器，然后：
cd /tmp && rm -rf nav210 && mkdir nav210 && cd nav210
unzip -o /path/to/nav-v2.1.0-deploy.zip

SR=/www/wwwroot/nav

# 后端 + 配置（cp -a api/. 是「覆盖内容」，不会先删目录，站点不会中断）
cp -a api/.    $SR/api/
cp -a config/. $SR/config/

# 前端产物「摊平」到站点根（老 assets 带 hash，直接换掉）
rm -rf $SR/assets
cp -a assets $SR/assets
cp -a index.html $SR/index.html
cp -a 48x48.ico  $SR/48x48.ico

# 属主与权限（注意：不要对 .user.ini 做 chown/chmod，它是 root + immutable）
find $SR/api $SR/config -type d -exec chmod 755 {} \;
find $SR/api $SR/config -type f -exec chmod 644 {} \;
chown -R www:www $SR/api $SR/config $SR/assets $SR/index.html $SR/48x48.ico

# 重载 PHP-FPM（清 opcache，并让 user_ini 缓存立即失效）
/etc/init.d/php-fpm-82 reload
```

新装（不是升级）请直接照 `部署说明-v2.0.0.md` 走，再补第 1 节这一步。

## 3. 「记住我」到底能保多久

| 勾选框 | 行为 |
| --- | --- |
| ✅ 勾选（默认） | 下发带过期时间的 Cookie（代码里写 10 年），**每次访问自动滑动续期**，续期间隔 30 天 |
| ⬜ 不勾 | 只发浏览器会话 Cookie（**不带 expires**），关掉浏览器就失效 |

**为什么需要滑动续期**：PHP 只在「新建会话 / 重新生成会话 ID」时才发
`Set-Cookie`，日常请求不会重发 —— 所以 Cookie 的过期时间是**死的**，
登录那一刻往后拨 N 天，天天在用也会在第 N 天被踢。v2.1.0 改为主动顺延：
`bootstrap.php` 的 `nav_remember_session()` 在每个请求里检查，距离上次下发
超过 30 天就重新下发一次，把过期时间往后推。

**边界（如实说明）**：
- Chrome / Safari 对**单条 Cookie** 有约 **400 天**的硬上限。10 年这个数字会被
  浏览器截断成 400 天 —— 但因为续期间隔只有 30 天，实际效果仍然是「只要在用就
  不会掉线」。
- 连续 **12 个月以上完全没访问**，服务端会话文件会被 GC 回收，需要重新登录一次。
  对导航站来说这属于正常。

## 4. 验收清单

```bash
# ① 未登录：不应下发带 expires 的 Cookie（应只有 path/HttpOnly/SameSite）
curl -si 'http://nav.lan/api/index.php?action=home.index' | grep -i set-cookie
#   期望：nav_sid=...; path=/; HttpOnly; SameSite=Lax          ← 没有 expires

# ② 勾选记住我登录：应出现带 expires 的长期 Cookie（两条，以后一条为准）
curl -si -X POST 'http://nav.lan/api/index.php?action=auth.login' \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"你的密码","remember":1}' | grep -i set-cookie
#   期望：第二条带 expires=...+10 年; Max-Age=315360000

# ③ 不勾记住我：只有不带 expires 的那一条
#   -d '{"username":"admin","password":"你的密码","remember":0}'

# ④ 会话文件必须落在独立目录，且内容里带 remember|i:1
ls -la /www/wwwroot/nav-data/sessions/
cat /www/wwwroot/nav-data/sessions/sess_*

# ⑤ /tmp 里不应再有本站会话（能看到的都属其他 PHP 程序）
ls /tmp | grep sess_

# ⑥ 版本号
curl -s 'http://nav.lan/api/index.php?action=releases.list' | head -c 200
```

浏览器侧验收：`http://nav.lan/#/login` → 勾上「记住我」登录 → 关掉整个浏览器 →
再打开 `http://nav.lan/` → 应该**仍然是登录状态**。

## 5. ⚠️ 顺带发现：`/test/` 是个开放代理（未处理，需你决定）

站点根下有一个**重构前（v1）留下的**目录 `/www/wwwroot/nav/test/`：

| 文件 | 情况 |
| --- | --- |
| `proxy.php` | 「通用模型 API 代理」，把 POST 过来的 `{base_url, api_key, path, body}` 转发到任意地址，并且带 `Access-Control-Allow-Origin: *` |
| `index.html` | 对应的调用页面 |

实测 `http://nav.lan/test/proxy.php` 返回 **405**（说明它**在正常运行**，
只是不接受 GET）—— 它能把本站当成**任意地址的转发跳板**（SSRF / 开放代理），
而且 `Allow-Origin: *` 意味着你在浏览器里打开的任何网页都能调它。

**本次没有动它**（不清楚你是否还在用这个工具）。确认不需要后删掉：

```bash
mv /www/wwwroot/nav/test /www/backup/nav-test-$(date +%Y%m%d)
/etc/init.d/php-fpm-82 reload
```

`make_release.py` 已经把 `test/` 从部署包里排除，不会再扩散到新部署。

另外提醒：`admin` 账号目前**仍是默认密码 `admin123`**，且
`force_password_change` 标记为空。建议尽快改掉。
